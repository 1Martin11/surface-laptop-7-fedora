  AusgangslageStarting point
  Die Maschine beschreibt sich selbst nicht
  The machine does not describe itself

  Auf x86-Geräten meldet ACPI dem Kernel, welche Hardware verbaut ist und wie sie angeschlossen wird. Auf den Snapdragon-Laptops übernimmt das der Device Tree — und der beschreibt für dieses Modell bislang nur einen Teil des Geräts. Alles, was dort fehlt, existiert für Linux schlicht nicht: kein Modul hilft, keine Konfigurationsdatei.
  On x86 machines, ACPI tells the kernel what hardware exists and how it is wired. On the Snapdragon laptops that job belongs to the device tree — and for this model it currently describes only part of the machine. Anything missing there simply does not exist as far as Linux is concerned: no module helps, no config file.

  Der zweite wiederkehrende Punkt: mehrere Bausteine brauchen Firmware, die Microsoft und Qualcomm nicht frei verteilen. Sie liegt aber auf der eigenen Platte — im Windows-Treiberspeicher. Fast jeder Fix hier folgt demselben Muster.
  The second recurring theme: several components need firmware that Microsoft and Qualcomm do not ship freely. It is sitting on your own disk though — in the Windows driver store. Nearly every fix here follows the same pattern.

  
    Zur WeitergabeOn redistribution
    Die Firmware- und Kalibrierungsdateien gehören Microsoft und Qualcomm. Sie werden hier nicht verteilt. Beschrieben ist nur der Weg — jeder holt sie aus seiner eigenen Windows-Installation.
    The firmware and calibration files belong to Microsoft and Qualcomm. They are not distributed here. Only the method is described — everyone extracts them from their own Windows installation.
  

  Windows-Partition einhängen
  Mount the Windows partition
  Fast alles Folgende beginnt damit. Die Partition mit lsblk -f heraussuchen — es ist das große NTFS-Volume.
  Nearly everything below starts here. Find the partition with lsblk -f — it is the large NTFS volume.
sudo mkdir -p /mnt/win

  Scheitert das Einhängen, ist in Windows noch der Schnellstart aktiv. Dann dort abschalten und einmal vollständig herunterfahren.
  If mounting fails, Windows Fast Startup is still enabled. Disable it there and shut down fully once.

  Zwei unabhängige Probleme übereinander. Nur eins zu lösen bringt nichts.
  Two independent problems stacked. Fixing only one gets you nowhere.

  Problem 1 — keine Kalibrierungsdaten
  Problem 1 — no board data
  ath12k braucht eine gerätespezifische Kalibrierungsdatei. linux-firmware liefert Einträge für jeden anderen X1E-Laptop, aber für kein Surface:
  ath12k needs a per-machine calibration file. linux-firmware ships entries for every other X1E laptop, but for no Surface:
ath12k_wifi7_pci 0004:01:00.0: failed to fetch board data for
  bus=pci,vendor=17cb,device=1107,subsystem-vendor=17cb,
  subsystem-device=1107,qmi-chip-id=2,qmi-board-id=255
  from ath12k/WCN7850/hw2.0/board-2.bin
  board-id=255 heißt: der Treiber konnte gar keine ID aus dem Chip lesen. Normalerweise liefert sie die Device-Tree-Eigenschaft qcom,ath12k-calibration-variant — die für romulus fehlt.
  board-id=255 means the driver could not read an ID from the chip at all. That normally comes from the device-tree property qcom,ath12k-calibration-variant, which romulus does not have.

  Problem 2 — rfkill meldet Hardware-Sperre
  Problem 2 — rfkill hard block
  Selbst mit geladener Firmware bleibt das Funkmodul gesperrt. ath12k überspringt die rfkill-Einrichtung nur, wenn ACPI ein entsprechendes Merkmal meldet. Auf Device-Tree-Geräten gibt es dafür kein Gegenstück, also nimmt der Treiber an, das Funkmodul sei abgeschaltet.
  Even with firmware loaded the radio stays blocked. ath12k only skips rfkill setup when ACPI advertises a matching flag. On device-tree machines there is no equivalent, so the driver assumes the radio is killed.
  Ein Dreizeiler dafür war Teil der Surface-Pro-11-Serie. Die Serie wurde im Januar 2026 aufgenommen — die rfkill-Patches flogen in v6 auf Wunsch der Reviewer raus: eine Eigenschaft disable-rfkill beschreibe keine Hardware, richtig wäre eine Quirk-Liste im Treiber. Die hat bis heute niemand eingereicht.
  A three-line fix was part of the Surface Pro 11 series. That series was merged in January 2026 — the rfkill patches were dropped in v6 at the reviewers' request: a disable-rfkill property describes no hardware, the correct fix would be a quirk list inside the driver. Nobody has submitted one since.

  Die .elf-Dateien verpacken die Rohdaten in einem ELF-Container. Offset und Länge des LOAD-Segments auslesen und herausschneiden:
  The .elf files wrap the raw data in an ELF container. Read the LOAD segment's offset and size, then cut it out:

# LOAD  0x000400 ... FileSiz 0x15400   →  1024 / 87040

   bs=1 skip=1024 count=87040 status=none
xxd /tmp/board.bin | head -1     # darf nicht mit 7f45 4c46 beginnen

  
    Der entscheidende PunktThe key point
    Firmware und Kalibrierung müssen gemeinsam getauscht werden. Die Windows-BDF mit der Firmware aus linux-firmware ergibt einen QMI-Timeout (board data file:-110), egal welche BDF man nimmt. Vier Kandidaten scheiterten identisch — bis auf die Hundertstelsekunde zur selben Zeit. Das war der Hinweis, dass es nicht an der Datei lag.
    Firmware and board data must be replaced together. The Windows BDF combined with linux-firmware's own firmware yields a QMI timeout (board data file:-110) whatever BDF you pick. Four candidates failed identically — to the hundredth of a second at the same moment. That was the clue that the file was not the problem.

  Akkuanzeige und die Coprozessoren
  Battery reporting and the coprocessors
  Ohne ADSP kein Akkustand — und ohne Akkustand keine Warnung, bevor das Gerät ausgeht.
  No ADSP, no battery level — and no warning before the machine dies.

  Der Akku hängt am Audio-DSP: qcom-battmgr spricht über den ADSP mit der Ladeelektronik. Läuft der nicht, existiert /sys/class/power_supply/qcom-battmgr-bat/ zwar, liefert aber bei jedem Wert EAGAIN.
  The battery hangs off the audio DSP: qcom-battmgr talks to the charger through the ADSP. If that is not running, /sys/class/power_supply/qcom-battmgr-bat/ exists but returns EAGAIN for every value.

  Firmware und PD-Maps
  Firmware and PD maps
  Nötig sind die Coprozessor-Abbilder, ihre Prozessdomänen-Beschreibungen und — leicht zu übersehen — die zugehörigen DTB-Dateien. Ohne Letztere meldet der Kernel Failed to load program segments / Boot failed: -2.
  You need the coprocessor images, their process-domain descriptions and — easily missed — the matching DTB files. Without those the kernel reports Failed to load program segments / Boot failed: -2.
sudo mkdir -p /lib/firmware/qcom/x1e80100/microsoft/Romulus

# ADSP:  surfacepro_ext_adsp8380.inf_arm64_*
#   qcadsp8380.mbn, adsp_dtbs.elf
#   adspr.jsn, adsps.jsn, adspua.jsn, battmgr.jsn
# CDSP:  qcsubsys_ext_cdsp8380.inf_arm64_*
#   qccdsp8380.mbn, cdsp_dtbs.elf, cdspr.jsn
  Der Kernel fragt die Dateien unter qcom/x1e80100/microsoft/Romulus/ an — mit Unterordner, anders als beim Zap-Shader. Nachzusehen in /sys/class/remoteproc/remoteproc*/firmware.
  The kernel requests these under qcom/x1e80100/microsoft/Romulus/ — with the subfolder, unlike the zap shader. Check /sys/class/remoteproc/remoteproc*/firmware.

  
    ZeitproblemTiming problem
    Von Hand gestartet läuft alles. Nach einem Neustart stehen beide Coprozessoren wieder auf offline: qcom_q6v5_pas probt schon bei 0,96 s, da ist /lib/firmware noch nicht verfügbar — und der Treiber versucht es kein zweites Mal.
    Started by hand, everything works. After a reboot both coprocessors are offline again: qcom_q6v5_pas probes at 0.96 s, before /lib/firmware is available — and the driver never retries.

  Gelöst · 23.08.2026Solved · 2026-08-23
  Touchpad — die lange Grabung
  Touchpad — the long dig
  Sieben Stationen: vom „gibt es nicht" bis zum funktionierenden Gerät. Der Reihe nach.
  Seven stages, from "it does not exist" to a working device. In order.

  1 · Es existiert nicht
  1 · It does not exist
  Ausgangsbefund: kein Touchpad, nirgends. Die Tastatur hängt am Surface Aggregator Module und ist dort das einzige Eingabegerät; ein Touchpad ist weder als HID-Gerät aufgezählt noch im Log erwähnt. Auch der SPI-Bus, an dem es hängen müsste, existiert im laufenden System nicht: Der Device Tree beschreibt zwar zwei Dutzend solcher Anschlüsse, aber alle sind abgeschaltet.
  Starting point: no touchpad anywhere. The keyboard hangs off the Surface Aggregator Module and is the only input device there; no touchpad is enumerated as a HID device, none is mentioned in the log. The SPI bus it would sit on does not exist in the running system either: the device tree describes two dozen such controllers, all disabled.

  2 · Windows verrät die Anschlusswerte
  2 · Windows gives up the wiring
  Was fehlt, ist die Beschreibung — und die steht unter Windows in den ACPI-Tabellen. Der Auszug der SSDT liefert alles auf einmal: Das Touchpad heißt dort MSHW0238, meldet sich als „HID over SPI", hängt am Controller QUP_2_SE_3 mit Basisadresse 0x88C000, läuft mit 20 MHz, hat seinen Interrupt auf GPIO 3 und wird über GPIO 65 und 120 mit Strom versorgt und zurückgesetzt.
  What is missing is the description — and under Windows it sits in the ACPI tables. The SSDT dump hands over everything at once: the touchpad is called MSHW0238, identifies as "HID over SPI", hangs off controller QUP_2_SE_3 at base address 0x88C000, runs at 20 MHz, has its interrupt on GPIO 3, and is powered and reset through GPIO 65 and 120.
  Ein Abgleich bestätigt die Zuordnung: Der Knoten spi@88c000 im Device Tree trägt exakt die Interruptnummer, die auch die ACPI-Tabelle nennt. Damit sind alle Angaben beisammen, um das Gerät zu beschreiben.
  A cross-check confirms the mapping: the node spi@88c000 in the device tree carries exactly the interrupt number the ACPI table names. So everything needed to describe the device is in hand.

  3 · Der Bootloader hilft nicht
  3 · The bootloader is no help
  Naheliegend wäre, den Device Tree zu ändern und den Bootloader den geänderten laden zu lassen. Genau das schlug fehl — mit GRUB wie mit systemd-boot, mit binär geflickter wie mit sauber neu übersetzter Datei. Der Beweis war ein Sabotage-Test: Die Datei wurde absichtlich zerstört, das System startete trotzdem normal durch. Der Baum kam also nie beim Kernel an.
  The obvious route would be to modify the device tree and have the bootloader load the modified one. That failed — with GRUB and with systemd-boot, with a binary-patched file and a cleanly recompiled one. The proof was a sabotage test: the file was deliberately corrupted and the system still booted normally. The tree never reached the kernel.

  
    Aufgeklärt · 23.08.2026Explained · 23 Aug 2026
    Die Erklärung kam später aus dem linux-surface-Thread, von valpackett: Ubuntus arm64-Kernel sind mit stubble gebaut, Canonicals Device-Tree-Stub. Der wählt anhand von Firmware-Kennungen einen von Dutzenden eingebetteten Bäumen und ersetzt damit den, den der Bootloader mitgibt. Nachgeprüft: Ubuntus Kernel enthält 33 solcher Bäume, der Kernel der Gemeinschaft keinen einzigen — dessen Autor lässt stubble bewusst weg, weil er selbst am Device Tree arbeitet.
    The explanation came later from the linux-surface thread, courtesy of valpackett: Ubuntu's arm64 kernels are built with stubble, Canonical's device-tree stub. It picks one of dozens of embedded trees based on firmware identifiers and replaces the one the bootloader hands over. Verified: Ubuntu's kernel carries 33 such trees; the community kernel carries none — its author deliberately leaves stubble out because he works on the device tree himself.
    Auf dem Kernel der Gemeinschaft funktioniert der Weg über den Bootloader also sehr wohl — nachgewiesen mit einer Markereigenschaft, die im laufenden Baum ankommt. Der hier beschriebene Umweg war für Ubuntus Kernel trotzdem nötig.
    So on the community kernel the bootloader route does work — demonstrated with a marker property that arrives in the running tree. The detour described here was still necessary on Ubuntu's kernel.
  

  4 · Der Umweg: Device Tree zur Laufzeit ändern
  4 · The detour: patching the device tree at runtime
  Wenn der Bootloader ausfällt, bleibt der laufende Kernel. Linux kann Device-Tree-Auflagen zur Laufzeit einhängen — über eine Schnittstelle, die in diesem Kernel nicht eingebaut ist. Also ein winziges eigenes Kernelmodul, das die Auflage einbettet und beim Laden anwendet. Es funktioniert auf Anhieb, und der Controller meldet sich prompt mit einer Fehlermeldung:
  If the bootloader is out, the running kernel remains. Linux can apply device-tree overlays at runtime — through an interface this kernel does not have compiled in. So: a tiny kernel module of our own that embeds the overlay and applies it on load. It works immediately, and the controller promptly answers with an error:
geni_spi 88c000.spi: Invalid proto 9
  Der Treiber kennt nur die Protokolle 0 bis 5. Die 9 steht für QSPI — dieselbe Bezeichnung, die auch in der ACPI-Tabelle steht. Und im Quelltext zeigt sich: Der Treiber lädt die passende Firmware für den Anschluss nur dann, wenn das Protokoll auf einem ganz bestimmten Ungültigkeitswert steht; bei jedem anderen bricht er ab. Ein Dreizeiler, die Firmware liegt ohnehin im System — und der Bus erscheint.
  The driver knows protocols 0 to 5 only. The 9 stands for QSPI — the same label that appears in the ACPI table. And the source reveals: the driver loads the controller's firmware only when the protocol reads a very specific invalid value; for anything else it bails out. A three-line change, the firmware is on the system anyway — and the bus appears.

  5 · Das Gerät hängt am Bus und schweigt trotzdem
  5 · The device is on the bus and stays silent anyway
  Mit dem Kindknoten für das Touchpad erscheint auch das Gerät. Der Treiber dafür existiert nur außerhalb des Kernels, ist aber schnell angepasst und bindet. Nur kommen keine Daten. Die Messungen darauf ergeben ein merkwürdiges Bild: Beim Senden ist alles vollständig, beim Lesen kommt exakt die Hälfte an — bei jeder Länge, jedem Takt, jeder Wortbreite, auf beiden Anschlüssen und auch mit ganz gewöhnlichem Testwerkzeug.
  Add the child node for the touchpad and the device shows up too. Its driver exists only outside the kernel, but adapts quickly and binds. Except no data arrives. The measurements produce an odd picture: sending is complete, reading returns exactly half — at every length, every clock rate, every word size, on both controllers, and with plain test tooling too.

  6 · Die Ursache: das Gerät spricht vierspurig
  6 · The root cause: the device speaks four-lane
  Die Auflösung steht in derselben ACPI-Tabelle, ein paar Zeilen weiter. Eine Abfragefunktion liefert die Betriebswerte des Geräts — und darunter zwei Befehlscodes und ein Merkmalsfeld:
  The resolution sits in the same ACPI table, a few lines further down. A query function returns the device's operating parameters — among them two opcodes and a flags field:
Funktion 4 → 0xEB   (Lesebefehl)
Funktion 5 → 0xE2   (Schreibbefehl)
Funktion 6 → 0xA000 (Merkmale)
  0xEB ist der Vierleitungs-Lesebefehl, 0xE2 sein Gegenstück zum Schreiben, und im Merkmalsfeld sind genau die Bits gesetzt, die den Vierleitungsbetrieb anfordern. Das Gerät redet also über vier Datenleitungen gleichzeitig — der Treiber liest über eine. Daher die Halbierung, und daher kein einziges brauchbares Byte.
  0xEB is the quad read opcode, 0xE2 its write counterpart, and the flags field has exactly the bits set that request quad mode. So the device talks over four data lines at once — the driver reads over one. Hence the halving, hence not a single usable byte.
  Im Mainline gibt es dafür nichts: Der SPI-Treiber meldet keine Mehrleitungsfähigkeit, und im Gerätetreiber steht an der entscheidenden Stelle ein Merkmalsfeld, das fest auf null gesetzt ist, mit einem Vermerk „Mehrleitungsbetrieb nicht unterstützt".
  Mainline has nothing for this: the SPI driver advertises no multi-lane capability, and in the device driver the decisive field is hard-coded to zero, with a note reading "multi-SPI not supported".

  7 · Es gibt sie doch — außerhalb des Mainlines
  7 · It does exist — outside mainline
  Im Kernel des ELLX-Projekts hat scuggo genau das implementiert: einen eigenen Gerätetyp für den Vierleitungsbetrieb, ausschließlich über DMA, mit dem Protokoll 9 als gültigem Wert und 0xEB als Vorgabe. Ein Satz aus diesem Patch erklärt rückblickend die ganze Grabung: Der Übertragungsweg über die Warteschlange kann einen vierspurigen Bus gar nicht bedienen. Alle Messungen an der Halbierung liefen über genau diesen Weg.
  In the ELLX project's kernel, scuggo implemented exactly this: a separate device type for quad mode, DMA only, with protocol 9 as a valid value and 0xEB as the default. One line from that patch explains the entire dig in hindsight: FIFO mode cannot drive a four-lane QSPI bus. Every halving measurement ran over precisely that path.
  Mit diesem Kernel bewegt sich der Zeiger. Aber auch nur das.
  With that kernel the pointer moves. But that is all it does.

  8 · Der letzte Zentimeter: der Daemon
  8 · The last inch: the daemon
  Kein Zwei-Finger-Scrollen, keine Gesten, kein Ziehen. Das Pad läuft dann in seiner einfachen Betriebsart — jener, die Microsoft für die Firmware-Oberfläche vorgesehen hat: ein Kontakt, sonst nichts. Für den Rest muss iptsd die rohen Wärmebilder des Sensors auswerten und daraus Fingerpositionen rechnen.
  No two-finger scrolling, no gestures, no dragging. The pad runs in its simple mode — the one Microsoft provided for the firmware interface: one contact, nothing more. For the rest, iptsd has to process the sensor's raw heatmaps and derive finger positions from them.
  Nur startete der Daemon nie. Tagelang schien es an Regeln und Diensten zu liegen — bis sich zeigte, dass das ausgelieferte Programm bei jedem Aufruf sofort abstürzt, selbst beim Anzeigen der Hilfe, ohne je ein Gerät zu berühren:
  Except the daemon never started. For days it looked like a matter of rules and services — until it turned out the shipped binary crashes immediately on every invocation, even printing its help text, without ever touching a device:
$ /usr/bin/iptsd --help
Illegal instruction (core dumped)
  Ursache sind uneinheitliche Sicherungsmaßnahmen für Sprungziele zwischen den Bauteilen des Pakets: Die Hardware verweigert einen indirekten Sprung, der auf keiner gültigen Landemarke aufsetzt. Aus dem Quelltext neu übersetzt — mit durchgängig gleichen Übersetzerschaltern — läuft dasselbe Programm fehlerfrei. Das dürfte jeden treffen, der dieses Paket auf entsprechender Hardware benutzt, unabhängig vom Gerät.
  The cause is inconsistent branch-protection settings between the package's components: the hardware refuses an indirect jump that lands on no valid marker. Rebuilt from source with consistent compiler flags, the very same program runs flawlessly. This likely affects anyone using this package on comparable hardware, whatever the device.

  9 · Ein Sensor, zwei Betriebsarten
  9 · One sensor, two modes
  Läuft der Daemon, entsteht ein zweites, virtuelles Eingabegerät neben denen des Kernels. Naheliegend ist die Annahme, dass dann beide gleichzeitig mit dem Desktop reden. Sie ist falsch. Gemessen über zehn Sekunden gleichmäßigen Wischens: mit laufendem Daemon senden alle fünf Kernel-Knoten exakt null Ereignisse, allein das virtuelle Gerät liefert — 3365 davon. Mit gestopptem Daemon liefert der Maus-Knoten des Kernels 2380 Ereignisse, darunter Bewegung auf beiden Achsen und acht saubere Tastendrücke. Der Sensor spricht entweder gewöhnliches HID oder das Vendor-Protokoll, nie beides. Es ist kein Wettstreit, sondern ein Betriebsartwechsel.
  Once the daemon runs, a second, virtual input device appears alongside the kernel's. The obvious assumption is that both then talk to the desktop at once. It is wrong. Measured over ten seconds of steady swiping: with the daemon running, all five kernel nodes emit exactly zero events, and only the virtual device reports — 3365 of them. With the daemon stopped, the kernel's mouse node delivers 2380 events, including motion on both axes and eight clean button presses. The sensor speaks either ordinary HID or the vendor protocol, never both. This is not a contest, it is a mode switch.
  Die Regel, die das rohe Gerät ausblendet, bleibt trotzdem sinnvoll — aber aus einem anderen Grund als gedacht. Der Multitouch-Knoten des Kernels wird nie beliefert; er ist in beiden Messungen stumm. Ausgeblendet wird also kein Konkurrent, sondern ein Gespenst: ein Touchpad, das der Desktop anbietet und das nie etwas meldet. Ausgeblendet wird ausschließlich dieser eine Knoten. Der Maus-Knoten bleibt sichtbar, und er ist der Zeiger, der übrig bleibt, wenn der Daemon einmal nicht läuft.
  The rule that hides the raw device still makes sense, but for a different reason than assumed. The kernel's multitouch node is never fed; it is silent in both runs. What gets hidden is not a competitor but a phantom: a touchpad the desktop offers and that never reports anything. Only that one node is hidden. The mouse node stays visible, and it is the pointer left over whenever the daemon is not running.
  Und selbst dann fehlte der Klick — aus demselben Grund. Sobald der Sensor in die Wärmebild-Betriebsart geschaltet wird, sendet er keine gewöhnlichen Tastenberichte mehr, und die ausgelieferte Fassung des Daemons reicht den Zustand nicht weiter. Gelöst hat es die Fassung von alex-lentz, deren Änderung genau diesen Pfad betrifft.
  And even then the click was missing — for the same reason. Once the sensor switches to heatmap mode it stops sending ordinary button reports, and the shipped release of the daemon does not forward the state. The fork by alex-lentz solved it; its change addresses exactly this path.
  Damit ist alles zusammen: Bewegung, Tippen, Ziehen, Zwei-Finger-Scrollen, Gesten und der physische Klick. Fenster lassen sich ziehen.
  With that, everything is in place: motion, tapping, dragging, two-finger scrolling, gestures and the physical click. Windows can be dragged.

  Zwei Fragen sind dabei auseinanderzuhalten. Wie man aus dem Zustand wieder herauskommt, ist ungeklärt — nachweislich hilft nur der Ausflug nach Windows, und der Kasten oben sagt genau das. Sie sind Vorbeugung, keine Heilung.
  Two questions need keeping apart here. How one gets out of the state is unresolved — demonstrably only the trip into Windows helps, and the box above says exactly that. How the state comes about is a different question, and for that there is a suspicion: the loss of the supply voltage mid-operation. The two sections below address that second question. They are prevention, not a cure.

  
    Die Verwechslung · 25.08.2026The look-alike · 25 Aug 2026
    Dazu gehört die Gegenprobe, und sie ist genauso wichtig: Ist nur das Touchpad tot, während der Touchscreen lebt, sieht das fast genauso aus — hat aber womöglich eine ganz andere Ursache. Die Gerätedateien der beiden Sensoren werden beim Start in wechselnder Reihenfolge vergeben. Über Wochen bekam das Touchpad immer dieselbe Nummer; bei einem Start im August fiel sie zum ersten Mal andersherum aus.
    There is a counterpart to this, and it matters just as much: if only the touchpad is dead while the touchscreen lives, it looks almost the same — but the cause may be entirely different. The two sensors' device files are handed out in varying order at boot. For weeks the touchpad always got the same number; on one boot in August it came out the other way round for the first time.
    Die beiden Ereignisse liegen rund fünfzig Millisekunden auseinander — ein Rennen, das wochenlang immer gleich ausging und deshalb wie eine Regel wirkte. Wer den Daemon auf eine feste Nummer verdrahtet, baut sich einen Fehler ein, der irgendwann zuschlägt, wie ein Hardwaredefekt aussieht und die Suche in die falsche Richtung schickt. Die Startdatei bindet ihn deshalb über den Anschlusspfad des Sensors, nicht über die Nummer.
    The two events are about fifty milliseconds apart — a race that came out the same way for weeks and therefore looked like a rule. Wiring the daemon to a fixed number builds in a fault that eventually strikes, looks like failing hardware, and sends the search in the wrong direction. So the unit resolves the device by the sensor's bus path instead of by its number.
  

  1 · Ordnungsgemäß abschalten
  1 · Shutting down in order
  Der Treiber meldet dem Kernel weder eine Abschalt- noch eine Energiespar-Rückrufadresse an. Beim Herunterfahren läuft für den Controller deshalb nichts: Er verliert die Versorgung mitten im Betrieb, statt vorher stillgelegt zu werden. Die Firmware macht es anders — ihre Abschaltmethode zieht erst den Reset, wartet zehn Millisekunden und nimmt dann die Spannung weg.
  The driver registers neither a shutdown nor a power-management callback. So when the machine powers off, nothing happens for the controller: it loses its supply mid-operation instead of being put to rest first. The firmware does it differently — its power-off method asserts reset, waits ten milliseconds, and only then removes the voltage.
  Eine kleine systemd-Unit bildet das nach. Sie zieht den Reset über die alte sysfs-GPIO-Schnittstelle, wartet, und entbindet dann den Treiber. Die Versorgung schaltet sie nicht selbst ab — das übernimmt der Kernel, denn das Entbinden führt über spi_hid_power_down() auf regulator_disable(). Aus dem Userspace lässt sich ein Regler ohnehin nicht abschalten; der Umweg über den Treiber ist nicht der bequemere, sondern der einzig saubere.
  A small systemd unit reproduces that. It asserts reset through the old sysfs GPIO interface, waits, then unbinds the driver. It does not switch the supply off itself — the kernel does, because unbinding runs through spi_hid_power_down() into regulator_disable(). Userspace cannot switch off a regulator anyway; going through the driver is not the more convenient route, it is the only clean one.
# Reset ziehen, 10 ms warten, dann erst entbinden
echo 632 > /sys/class/gpio/export
echo low > /sys/class/gpio/gpio632/direction
sleep 0.01
echo spi0.0 > /sys/bus/spi/drivers/spi_hid/unbind
  Gemessen im Trockentest über systemctl stop und beim echten Herunterfahren: Der Abstand zwischen Reset und Wegfall der Versorgung liegt bei 14 bis 15 Millisekunden, und der Regler steht danach auf state=disabled num_users=0. Die Unit schreibt ihre eigenen Messwerte ins Journal, damit sich das nach jedem Start nachlesen lässt statt es zu glauben.
  Measured in a dry run via systemctl stop and during a real shutdown: the gap between reset and loss of supply comes out at 14 to 15 milliseconds, and the regulator afterwards reads state=disabled num_users=0. The unit writes its own measurements to the journal, so after every boot this can be read rather than assumed.
ts-powerdown: Reset gezogen: GPIO 120 = sysfs 632 auf low

  Ein Detail, an dem man sich sonst das falsche Gerät abschaltet: Der Regler ist über seinen Namen aufzulösen, nie über die Instanznummer — die wechselt von Start zu Start. Und der Name muss genau verglichen werden, denn der des Touchscreens unterscheidet sich nur um ein Zeichen.
  One detail that otherwise powers down the wrong device: resolve the regulator by its name, never by its instance number — that changes from boot to boot. And compare the name exactly, because the touchscreen's differs by a single character.

  
    Vorbeugung, keine HeilungPrevention, not a cure
    Ob das den Aussetzer verhindert, ist nicht bewiesen. Die Überlegung dahinter ist plausibel und mehr nicht: Ein Controller, dem die Spannung mitten im Betrieb wegbricht, könnte in einem Zustand landen, aus dem ihn kein Neustart mehr holt. Ob es sich so verhält, zeigen erst Wochen ohne neuen Ausfall — und selbst dann wäre es ein Indiz, kein Beweis.
    Whether this prevents the outage is not proven. The reasoning behind it is plausible and no more: a controller whose voltage collapses mid-operation might end up in a state no reboot can clear. Only weeks without another failure would show whether that is so — and even then it would be an indication, not proof.
    Deshalb gehört der Rückweg zur Maßnahme. Ein einziges systemctl disable ts-powerdown.service schaltet sie folgenlos ab: Ohne den Verweis im Startziel wird die Unit nie gestartet, also nie gestoppt, also läuft ihr Abschaltteil nie. Bei einer unbewiesenen Hypothese ist das kein Zusatz, sondern Teil des Entwurfs.
    So the way back is part of the measure. A single systemctl disable ts-powerdown.service switches it off without a trace: with no link from the boot target the unit is never started, therefore never stopped, therefore its shutdown half never runs. With an unproven hypothesis that is not an extra, it is part of the design.
  

  2 · Ein Eigentümer je Leitung
  2 · One owner per line
  GPIO 65 schaltet die 5-Volt-Schiene des Touchpads. Im Device Tree steht diese Leitung zweimal: einmal als Freigabeleitung des Reglers, einmal in den beiden pinctrl-Zuständen des Sensorknotens, wo sie gemeinsam mit der Reset-Leitung GPIO 120 geführt wird. Zwei Mechanismen besitzen dieselbe Leitung, und sie widersprechen sich.
  GPIO 65 switches the touchpad's 5-volt rail. The device tree describes that line twice: once as the regulator's enable line, and once inside the two pin control states of the sensor node, where it is driven together with the reset line GPIO 120. Two mechanisms own the same line, and they disagree.
  Beim Anlaufen hebt der Zustand active Versorgung und Reset im selben Augenblick. Die 100 Millisekunden Anlaufverzögerung des Reglers laufen dabei durchaus — sie sitzen nur hinter der Reset-Freigabe statt davor. Die Firmware macht es umgekehrt: erst Spannung, dann warten, dann Reset lösen. Solange beide Leitungen in demselben pinctrl-Zustand stehen, lässt sich diese Reihenfolge nicht einmal ausdrücken.
  During bring-up the active state raises supply and reset in the very same instant. The regulator's 100-millisecond startup delay does run — it merely sits behind the reset release instead of in front of it. The firmware does the opposite: voltage first, then wait, then release reset. As long as both lines live in the same pin state, that ordering cannot even be expressed.
  Die zweite Erscheinungsform desselben Fehlers: Dem Reglerknoten fehlt die Angabe, dass die Schiene beim Start bereits an ist. Deshalb fordert der Reglertreiber seine Freigabeleitung als Ausgang, low an und zieht GPIO 65 in dem Moment aktiv auf Masse, in dem er gebunden wird — er schneidet die Versorgung eines Geräts ab, das die Firmware längst hochgefahren hatte. Beides ist derselbe Fehler an zwei Orten: Die Schiene ist nicht als Eigentum des Reglers beschrieben.
  The same mistake shows up a second time: the regulator node does not declare that the rail is already up at boot. So the regulator driver requests its enable line as output, low and actively pulls GPIO 65 to ground the moment it binds — cutting the supply of a device the firmware had long since powered. Both are one mistake in two places: the rail is not described as belonging to the regulator.
  spi19-hid0-reset-deassert-state {
-     pins = "gpio65", "gpio120";
+     pins = "gpio120";
  spi19-hid0-reset-assert-state {
-     pins = "gpio65", "gpio120";
+     pins = "gpio120";
  ts-5p0-regulator {
+     regulator-boot-on;
  Danach gehört die Schiene allein dem Regler, und der Start wird der, den die Firmware vorsieht: Spannung steht, Reset 300 Millisekunden gezogen, Reset gelöst. Zusätzliche pinctrl-Zustände braucht es dafür nicht — die beiden vorhandenen beschreiben jetzt nur noch die Reset-Leitung, und die Versorgung führt der Regler. Belegt im Testboot über die Tracepoints des Reglerkerns:
  After this the rail belongs to the regulator alone, and bring-up becomes what the firmware intends: voltage up, reset asserted for 300 milliseconds, reset released. No additional pin states are needed — the two existing ones now describe the reset line only, and the regulator leads the supply. Evidence from a test boot, via the regulator core's tracepoints:
1,609 s   regulator_enable            vreg_ts_5p0
1,715 s   regulator_enable_complete   vreg_ts_5p0    (+106 ms, die Anlaufverzoegerung)
5,297 s   input: spi 045E:0C77 ...    das erste Eingabegeraet erscheint
5,597 s   regulator_enable            vreg_ts2_5p0   (Kontrolle: Touchscreen, ungepatcht)
  Die Schiene steht also 3,7 Sekunden bevor das erste Eingabegerät erscheint, und dazwischen liegt kein Abschalten des Reglers. Die Kontrolle liegt in derselben Messung: Der unveränderte Touchscreen-Regler schaltet erst bei 5,597 Sekunden ein — angestoßen vom udev-Arbeiter beim Treiberstart, also genau so spät, wie es beim Touchpad vorher auch war. Der Abstand zwischen diesen beiden Zeitpunkten ist die ganze Wirkung des Patches.
  So the rail is up 3.7 seconds before the first input device appears, with no regulator disable in between. The control sits in the same measurement: the unmodified touchscreen regulator only switches on at 5.597 seconds — triggered by the udev worker at driver start, exactly as late as the touchpad used to be. The distance between those two timestamps is the entire effect of the patch.

  
    Dieser Patch ist nicht additivThis patch is not additive
    Anders als die Touchscreen-Ergänzung fügt er nichts hinzu, sondern greift in ELLXs Basis-DTSI ein — in fremden, laufenden Code. Deshalb bekommt er einen eigenen GRUB-Testeintrag, und das festgezurrte DTB bleibt unangetastet: Der normale Eintrag bootet weiter die bewährte Fassung, solange sich die neue nicht bewährt hat. Beide Device-Tree-Patches liegen als Commits auf einem eigenen Zweig, nicht als Bastelei am Binärformat.
    Unlike the touchscreen addition it adds nothing; it edits ELLX's base DTSI — someone else's running code. So it gets a GRUB entry of its own, and the pinned device tree blob stays untouched: the normal entry keeps booting the proven build for as long as the new one has not proven itself. Both device tree patches live as commits on a branch of their own, not as edits to the binary.
    Der Touchscreen hat denselben Defekt auf GPIO 64 und bleibt bewusst unangetastet. Er ist die gesunde Referenz, gegen die das Touchpad gemessen wird — und die verliert man in dem Moment, in dem man beide Hälften gleichzeitig ändert.
    The touchscreen has the same defect on GPIO 64 and is deliberately left alone. It is the healthy reference the touchpad is measured against — and that reference is lost the moment both halves are changed at once.

  Sicherung auf einen Heimserver
  Backups to a home server
  Nicht gerätespezifisch — aber wer so viel am laufenden System schraubt, braucht sie.

  Gesichert wird mit borg 1.4 über SSH auf einen Rechner im eigenen Netz. Der Schlüssel, mit dem sich die Maschine dort anmeldet, ist auf genau eine Aufgabe eingeschränkt: Er darf den Sicherungsdienst starten, sonst nichts, und auch den nur für ein einziges Archivverzeichnis.

  Was gesichert wird, steht in einer Musterdatei statt in der Befehlszeile. Die wurde gegengeprüft, bevor sie in Betrieb ging: borg create --dry-run --list zeigt für einen vollständigen Durchlauf, welche Pfade aufgenommen und welche verworfen würden, ohne etwas zu schreiben.

  Ausgelöst wird täglich, aber nicht zu einer festen Uhrzeit: Der Zeitgeber hat mehrere Termine über den Tag verteilt, damit auch ein Laptop drankommt, der morgens um sieben noch zugeklappt war. Damit daraus nicht mehrere Sicherungen am Tag werden, setzt ein gelungener Lauf eine Erfolgsmarke, und die folgenden Termine sehen zuerst dort nach.
  It fires daily, but not at a fixed hour: the timer has several slots spread across the day, so a laptop still shut at seven in the morning gets its turn too. To keep that from producing several backups a day, a successful run sets a marker, and the later slots check it first.
  Dazu ein Wächter, der nichts sichert, sondern nur nachsieht: Ist die jüngste Sicherung im Archiv älter als drei Tage, meldet er sich. Er ist der wichtigste Teil des Ganzen, denn ein Backup, das niemand prüft, ist eine Vermutung.
  Alongside it runs a watchdog that backs up nothing and only looks: if the newest archive in the repository is older than three days, it reports. It is the most important piece of the whole arrangement, because a backup nobody checks is a guess.

  
    Fallstrick 1 — die Liste zeigt auch das AusgeschlosseneTrap 1 — the list shows what was excluded too
    Die Ausgabe von --list enthält auch die verworfenen Pfade, gekennzeichnet mit einem x am Zeilenanfang; aufgenommene tragen dort ein -. Wer die Ausgabe nach einem Dateinamen durchsucht und ihn findet, hat damit nichts bewiesen — er kann als x dringestanden haben. Die Suche muss das Kennzeichen mitlesen und am Zeilenanfang verankern.
    The output of --list contains the discarded paths as well, marked with an x at the start of the line; included ones carry a - there. Searching that output for a filename and finding it proves nothing — it may have been sitting there as an x. The search has to read the marker and anchor at the start of the line.
  

  
    Fallstrick 2 — ein stiller Abbruch sieht aus wie ErfolgTrap 2 — a silent abort looks like success
    Bricht ein Lauf ab, ohne dass der Rückgabewert das meldet — Null trotz unvollständigem Archiv —, dann ist ein dauerhaft kaputtes Backup von einem gelungenen nicht zu unterscheiden. Der Rückgabewert allein taugt deshalb nicht als Erfolgsmerkmal. Die Erfolgsmarke wird erst gesetzt, wenn das Archiv danach auch tatsächlich auffindbar ist, und der Wächter prüft unabhängig davon das Alter der jüngsten Sicherung.

The exit status alone is therefore not a success criterion. (function(){
  var html = document.documentElement;
  var de = document.getElementById('de');
  var en = document.getElementById('en');
  var th = document.getElementById('theme');

  function setLang(l){
    html.setAttribute('data-lang', l);
    html.setAttribute('lang', l);
    de.setAttribute('aria-pressed', l === 'de');
    en.setAttribute('aria-pressed', l === 'en');
    document.title = (l === 'de')
      ? 'Surface Laptop 7 unter Linux — Protokoll'
      : 'Linux on the Surface Laptop 7 — working log';
  }
  de.addEventListener('click', function(){ setLang('de'); });
  en.addEventListener('click', function(){ setLang('en'); });

  th.addEventListener('click', function(){
    var dark = html.getAttribute('data-theme') === 'dark';
    html.setAttribute('data-theme', dark ? 'light' : 'dark');
    th.setAttribute('aria-pressed', String(!dark));
    th.textContent = dark ? '☾' : '☀';
  });

  if (window.matchMedia && window.matchMedia('(prefers-color-scheme: dark)').matches){
    html.setAttribute('data-theme','dark');
    th.setAttribute('aria-pressed','true');
    th.textContent = '☀';
  }
})();
